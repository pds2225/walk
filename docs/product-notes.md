# walk 제품 메모

기능 결정의 배경이 되는 사용자·현장 조건을 모아 둔다. 코드 주석으로 흩어지면
"왜 이렇게 만들었는지"가 사라지므로 여기에 남긴다.

## 대상 사용자

- **노인 이용자를 포함한다.** 실험적 프로토타입이 아니라 실제 보행 약자가 쓴다는
  전제로 화면과 안내를 설계한다.
- **지팡이를 쓰면 폰을 들고 지도를 볼 손이 없다.** 한 손은 지팡이, 다른 손은
  난간·가방 등에 쓰인다.

### 여기서 나오는 설계 원칙

1. **음성이 1순위, 화면은 보조.** 화면을 보지 않아도 길을 갈 수 있어야 한다.
   회전 예고·이탈 경고·재탐색 성공은 모두 음성으로 알린다. 음성 안내 기본값은 ON.
2. **화면을 볼 때는 한 번에 알아봐야 한다.** 첫 화면은 목적지 입력과 출발 버튼
   2개(걷기 / 대중교통+걷기)만 남기고 나머지는 '⋯ 더보기'로 접는다.
3. **큰 글씨·큰 터치 타깃.** 버튼 높이 56px 이상, 본문 17px 이상. 아이콘만으로
   뜻을 전달하지 않는다(아이콘 없이 글씨로).
4. **잦은 경고는 해롭다.** 걷는 중 반복 경고는 주의를 뺏고 위험하다 — 제자리·왕복
   구간 억제, 20초 재발화 쿨다운, 복귀 히스테리시스가 모두 이 원칙에서 나왔다.
5. **배경은 흰색 고정.** 야외 명암 대비를 일정하게 유지한다(기기 다크모드 무시).
6. **랜드마크 안내가 중요하다.** "CU편의점을 지나 왼쪽" 처럼 눈에 보이는 기준점을
   말해 주면 화면을 보지 않고도 방향을 확인할 수 있다.

### 아직 반영하지 않은 것

- 이어폰·블루투스 연결 시 음성 우선 모드
- 화면 완전 소등 상태에서의 음성 안내(백그라운드 오디오)
- 진동 패턴만으로 좌/우 구분
